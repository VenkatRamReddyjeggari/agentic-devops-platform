# orders-api reference

A small Flask service that stores orders in DynamoDB. Source: [`app/app.py`](../app/app.py).

## Endpoints

| Method | Path | Success | Errors |
|---|---|---|---|
| `GET` | `/healthz` | `200 {"status":"ok"}` | (none) |
| `GET` | `/readyz` | `200 {"status":"ready","version":…,"uptime_s":…}` | `503` if `ORDERS_TABLE` is not set |
| `POST` | `/orders` | `201` + the created order | `400` invalid input, `503` storage error |
| `GET` | `/orders` | `200` + array of orders, oldest first | `503` storage error |
| `GET` | `/orders/<id>` | `200` + the order | `404` unknown or malformed id, `503` storage error |

### Order object

```json
{
  "id": "3f2a9c1e-7b4d-4e2a-9f10-2c8d5e6b7a90",
  "item": "widget",
  "quantity": 3,
  "status": "created",
  "created_at": "2026-10-16T00:31:26.123456+00:00"
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | string (UUID v4) | Generated by the server |
| `item` | string | Trimmed; 1–200 characters |
| `quantity` | integer | ≥ 1; defaults to 1; booleans are rejected |
| `status` | string | Always `created` today |
| `created_at` | string (ISO 8601, UTC) | Used to sort `GET /orders` |

### Create an order

```bash
curl -s -X POST localhost:8080/orders \
  -H 'Content-Type: application/json' \
  -d '{"item": "widget", "quantity": 3}'
```

Validation errors return `400` with a message:

| Input | Error |
|---|---|
| missing, empty or whitespace `item` | `'item' is required` |
| `item` longer than 200 characters | `'item' must be at most 200 characters` |
| `quantity` 0, negative, a string or a boolean | `'quantity' must be a positive integer` |

### Fetch and list

```bash
curl -s localhost:8080/orders/3f2a9c1e-7b4d-4e2a-9f10-2c8d5e6b7a90
curl -s localhost:8080/orders
```

Non-UUID ids (for example `/orders/1`) return `404` without calling DynamoDB.

## Configuration

| Variable | Required | Meaning |
|---|---|---|
| `ORDERS_TABLE` | yes | DynamoDB table name. Without it, `/readyz` returns 503 and order endpoints fail. |
| `AWS_REGION` | in EKS: injected by IRSA | Region of the table. The chart sets it only if `ordersTable.region` is set. |
| `AWS_ENDPOINT_URL` | no | Point boto3 at DynamoDB Local for laptop runs. |
| `APP_VERSION` | no | Reported by `/readyz`; the chart sets it from `env.APP_VERSION`. |
| `PORT` | no | Port for `python app.py` (default 8080). The container always listens on 8080. |

Credentials come from boto3's default chain: IRSA in EKS, your AWS profile locally.

## Behavior notes

- **Durability:** orders live in DynamoDB, so they survive pod restarts and are shared by
  all pods and workers.
- **No overwrites:** `PutItem` uses `attribute_not_exists(id)`.
- **Consistency:** `GET /orders/<id>` uses a strongly consistent read, so an order is
  visible right after it is created. `GET /orders` uses a scan (eventually consistent).
- **Scale limit:** `GET /orders` reads the whole table. Add pagination parameters and a
  GSI on `created_at` before the table holds more than a few thousand orders.
- **Timeouts:** 2 s connect, 5 s read, up to 3 attempts. Failures return 503 and are
  logged with the message `DynamoDB call failed`.
- **Server:** gunicorn, 2 workers × 4 threads, `--worker-tmp-dir /tmp` (the root
  filesystem is read-only). Workers are stateless.

## Tests

[`app/test_app.py`](../app/test_app.py) runs 19 tests against a mocked DynamoDB
([moto](https://github.com/getmoto/moto)), so no AWS account is needed. They cover
health and readiness, create/get/list, persistence across a store restart, ordering,
validation, 404s, storage errors (503) and concurrent creates.

```bash
cd app && pytest -q        # Python 3.12
```
